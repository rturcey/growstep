#62 — Tiled PoC #4 — Extraire les objets Tiled vers le pipeline existant
======================================================================

## Parent

#58

## What to build

Parser les object layers (`props`, `plots`) depuis le `TiledMap` chargé et convertir le rocher en `GardenSpriteObject` rendu via le pipeline `_SceneObject` existant. Mesurer le delta d'ancre entre Tiled `bottom-center` et le manifeste, et appliquer un offset déterministe si nécessaire. Les 8 plots sont lus depuis Tiled mais ne remplacent pas `PotagerPlots` au runtime dans ce PoC.

**Le rocher pilote devient Tiled-authoritative.** Son ancien placement Dart cesse d'être rendu ; sa position provient exclusivement du TMX. Aucun fallback sur sa coordonnée Dart n'existe. Cela crée une exception assumée au principe « composition Dart intacte » du PoC, mais elle est indispensable pour prouver réellement le point 9 : Tiled → changement visible sans coordonnée Dart.

Avant ce ticket :
```
east_upper_rock position → Dart
```

Après ce ticket :
```
east_upper_rock position → potager_diorama_v1.tmx exclusivement
Dart  → asset / anchor / depth / rendering
Tiled → gridCol / gridRow
```

## Acceptance criteria

- [ ] Les object layers `props` et `plots` sont parsées depuis le `TiledMap`
- [ ] Le rocher est extrait comme `GardenSpriteObject` (ID stable, asset, contact calculé via l'adapter, size, layer) et rendu via `_SceneObject` dans le pipeline de profondeur existant
- [ ] Le rocher pilote n'a qu'une seule instance runtime. Son ancien placement Dart (`PotagerPilotScene.rock`) est retiré/désactivé du rendu ; sa position provient exclusivement du TMX. Aucun fallback sur sa coordonnée Dart n'existe.
- [ ] Le delta d'ancre entre `Tiled bottom-center` et `manifest ground anchor` est mesuré sur le rocher et documenté
- [ ] Si le delta n'est pas nul, un offset déterministe dérivé du manifeste est appliqué (pas de correction manuelle par objet, pas de modification des PNG)
- [ ] Les 8 plots sont lus depuis Tiled (`gridCol/gridRow` → contacts via l'adapter) mais `PotagerPlots` reste autoritaire au runtime — les plots Tiled sont shadow/read-only
- [ ] Widget test (`potager_scene_test.dart`) : les 8 contacts historiques restent tapables aux deux viewports (390×844, 375×667)
- [ ] Le hit testing ne dépend pas des bounds de sprites Tiled ; le contact logique reste autoritaire
- [ ] Le rocher apparaît au même endroit que dans le rendu actuel (à l'offset d'ancre près)

## Blocked by

- #61 (le RenderableTiledMap doit être chargé et rendu avant d'extraire les objets)


#63 — Tiled PoC #5 — Valider le workflow de bout en bout
======================================================================

## Parent

#58

## What to build

Valider que modifier la carte dans Tiled produit un changement visible dans Growstep sans modifier aucune coordonnée Dart. Ce ticket prouve les 9 critères de réussite du PoC et produit les captures pour la revue visuelle externe.

Le protocole de manipulation est une vraie preuve, sans dégrader la map finale : partir d'une position A connue du rocher, le déplacer exactement d'une cellule vers B dans Tiled, générer une capture prouvant B, puis remettre la map canonique à la position choisie avant le commit final. Même chose pour paint/depaint : prouver les deux états, puis conserver seulement l'état final souhaité.

L'AC « revue visuelle externe » reste un gate humain : l'agent d'implémentation produit les captures mais ne coche pas lui-même la validation visuelle.

## Acceptance criteria

- [ ] Déplacer le rocher d'une cellule dans Tiled (position A → position B) → capturer que Growstep affiche B et non A → remettre la map canonique à la position choisie avant le commit final
- [ ] Peindre de nouvelles pierres dans la couche `path` → capturer qu'elles apparaissent dans Growstep → remettre l'état final souhaité
- [ ] Dépeindre des pierres → capturer qu'elles disparaissent dans Growstep → remettre l'état final souhaité
- [ ] Captures couleur et niveaux de gris produites à 390×844 et 375×667
- [ ] Revue visuelle externe (gate humain, pas coché par l'agent) : pierres aux cellules attendues, terrain Canvas visible, pierres entre terrain et objets dynamiques, anchor/depth du rocher correct, aucun offset d'artboard introduit
- [ ] Les 9 critères de réussite du PoC sont tous validés :
  1. Map Tiled isométrique 80×40 ouverte et éditable
  2. Correspondance exacte grille Tiled → contacts Growstep (8 plots historiques)
  3. Tile layer `path` rendue correctement dans Growstep
  4. Tile de pas japonais 80×40 transparente (sprite existant, non redessiné)
  5. Objet vertical (rocher) ancré à une cellule
  6. Anchor manifest correctement compensé (delta mesuré, offset déterministe)
  7. Plot avec marker editor-only natif Tiled, invisible dans Growstep
  8. Rendu Tiled entre terrain Canvas et scène dynamique
  9. Modification dans Tiled → résultat visible dans Growstep sans coordonnée Dart

## Blocked by

- #62 (les objets Tiled doivent être extraits et rendus avant la validation finale)
